# Reproduce ViSpec with Qwen2.5-VL

This run follows ViSpec's two-stage training scheme with
`Qwen/Qwen2.5-VL-7B-Instruct`. Stage 1 trains a text-only EAGLE draft. Stage 2
adds ViSpec's image adaptor and multi-token rollout objective. Both datasets
must be regenerated by the same target checkpoint.

## Environment

Use conda for isolated Python prefixes and `uv` for every Python package. The
training and generation environments are intentionally separate: AutoModel
requires `nvidia-cutlass-dsl==4.6.0`, while vLLM 0.23 requires 4.5.2. Their
OpenCV pins also differ. Installing both into one prefix is not solvable without
overriding required binary dependencies.

Create the AutoModel training environment:

```bash
conda env create -f examples/speculative/vispec/environment.yml
conda activate automodel
uv pip install --python "$CONDA_PREFIX/bin/python" \
  -e ".[vlm,vlm-media]"
```

Create the vLLM data-generation environment and expose this checkout without
installing AutoModel's conflicting dependency set:

```bash
conda env create -f examples/speculative/vispec/environment-vllm.yml
conda activate automodel-vllm
uv pip install --python "$CONDA_PREFIX/bin/python" \
  "vllm==0.23.0" datasets qwen-vl-utils qwen-omni-utils torchdata pyyaml pillow \
  "pyarrow==20.0.0" "fsspec==2023.6.0"
uv pip install --python "$CONDA_PREFIX/bin/python" --no-deps -e .
```

Verify the environment on the GPU machine:

```bash
conda activate automodel
python -c "import torch, transformers, nemo_automodel; print(torch.__version__, transformers.__version__, torch.cuda.is_available())"
conda activate automodel-vllm
python -c "import torch, transformers, vllm; print(torch.__version__, transformers.__version__, vllm.__version__, torch.cuda.is_available())"
nvidia-smi
```

Set cache and output locations with enough space. The LLaVA-Pretrain repository
is about 28 GB before regenerated answers and checkpoints.

```bash
export HF_HOME=/data/huggingface
export VISPEC_DATA=/data/datasets/vispec_qwen2_5_vl
export VISPEC_RUNS=/data/runs
mkdir -p "$HF_HOME" "$VISPEC_DATA/stage1" "$VISPEC_DATA/stage2" "$VISPEC_RUNS"
```

## Stage 1 data with a vLLM server

Start the target server in one shell. Increase tensor parallelism when the
model does not fit on one GPU.

```bash
conda activate automodel-vllm
vllm serve Qwen/Qwen2.5-VL-7B-Instruct \
  --served-model-name Qwen/Qwen2.5-VL-7B-Instruct \
  --tensor-parallel-size 1 --max-model-len 4096 --max-num-seqs 64 --port 8000
```

Regenerate 68,000 text conversations in a second shell. The client sends up to
64 concurrent requests to the vLLM OpenAI-compatible endpoint and writes
resumable parquet shards.

```bash
conda activate automodel-vllm
python -m nemo_automodel.components.speculative.regenerate \
  --input-data Aeala/ShareGPT_Vicuna_unfiltered \
  --split 'train[:68000]' \
  --output-dir /data/datasets/vispec_qwen2_5_vl/stage1 \
  --target-server http://localhost:8000/v1 \
  --model Qwen/Qwen2.5-VL-7B-Instruct \
  --concurrency 64 --max-new-tokens 1024 --temperature 0
```

Stop the vLLM server before training so it releases its GPUs, then run stage 1:

```bash
conda activate automodel
automodel examples/speculative/vispec/qwen2_5_vl_vispec_stage1.yaml --nproc-per-node 1
```

The final consolidated safetensors checkpoint is written under
`/data/runs/vispec_qwen2_5_vl_stage1/checkpoints/LATEST/model/consolidated`,
which is already the `draft_init_from` value in the stage-2 YAML.

## Stage 2 multimodal data with offline vLLM

Download the exact annotation file and image archive instead of loading the
dataset repository as one split; that repository contains JSON files with
different schemas.

```bash
conda activate automodel-vllm
hf download liuhaotian/LLaVA-Pretrain \
  blip_laion_cc_sbu_558k.json images.zip \
  --repo-type dataset --local-dir /data/LLaVA-Pretrain
unzip /data/LLaVA-Pretrain/images.zip -d /data/LLaVA-Pretrain
```

First run a small smoke shard. It proves model loading, image paths, prompt
round-tripping, and vLLM batching without committing to the full generation.

```bash
conda activate automodel-vllm
python -m nemo_automodel.components.speculative.regenerate_vlm \
  --model Qwen/Qwen2.5-VL-7B-Instruct \
  --dataset /data/LLaVA-Pretrain/blip_laion_cc_sbu_558k.json \
  --image-root /data/LLaVA-Pretrain \
  --output-dir /data/datasets/vispec_qwen2_5_vl/stage2-smoke \
  --start 0 --end 8 --max-new-tokens 128 \
  --image-max-pixels 802816 \
  --engine vllm --batch-size 8 --tensor-parallel-size 1
```

Then generate the full 68,000-row training slice with long answers:

```bash
conda activate automodel-vllm
python -m nemo_automodel.components.speculative.regenerate_vlm \
  --model Qwen/Qwen2.5-VL-7B-Instruct \
  --dataset /data/LLaVA-Pretrain/blip_laion_cc_sbu_558k.json \
  --image-root /data/LLaVA-Pretrain \
  --output-dir /data/datasets/vispec_qwen2_5_vl/stage2 \
  --start 0 --end 68000 --max-new-tokens 1024 --temperature 1 \
  --image-min-pixels 200704 --image-max-pixels 1003520 \
  --engine vllm --batch-size 512 --tensor-parallel-size 1 \
  --gpu-memory-utilization 0.9 --max-model-len 4096
```

`batch-size` controls how many requests are submitted together, while vLLM
still schedules tokens dynamically. If the engine runs out of memory, lower
`batch-size` or `gpu-memory-utilization`; if the model itself does not fit, raise
`tensor-parallel-size` and expose that many GPUs.

## Stage 2 training

The generated `meta.json` is already the path configured by the recipe. Keep
`micro_batch_size: 1`; image-token sequences have variable effective lengths.

```bash
conda activate automodel
automodel examples/speculative/vispec/qwen2_5_vl_vispec.yaml --nproc-per-node 1
```

Watch `train/valid_tokens`: zero means image expansion and truncation removed
the assistant answer, so the step has no supervision. Both stages save final
consolidated safetensors for Hugging Face ecosystem compatibility.

## Transformers speed comparison

Use the same local prompts, fixed output length, BF16 target, SDPA backend, and
batch size one for both drafts. Run the autoregressive baseline separately and
pass its JSON to speculative runs with `--baseline-results`; DFlash and ViSpec
do not repeat baseline decoding. Starting at row 60000 avoids repeatedly
benchmarking the first training examples; this is a throughput experiment, not
a quality test.

Run DFlash:

```bash
.venv/bin/python tools/transformers_vlm_spec_bench.py \
  --target /data/models/Qwen2.5-VL-7B-Instruct \
  --draft /data/runs/dflash_qwen2_5_vl_7b/checkpoints/epoch_6_step_14574/model/consolidated \
  --mode dflash --verification-mode block \
  --input-data /data/datasets/vispec_qwen2_5_vl/stage2_clean/data.jsonl \
  --media-dir /data/LLaVA-Pretrain --input-start 60000 \
  --num-prompts 64 --max-new-tokens 512 --fixed-output-length \
  --attn-implementation sdpa \
  --output training_logs/dflash_local_64x512.json
```

Run the converted official ViSpec draft:

```bash
.venv/bin/python tools/transformers_vlm_spec_bench.py \
  --target /data/models/Qwen2.5-VL-7B-Instruct \
  --draft /data/models/ViSpec-Qwen2.5-VL-7B-Instruct-nemo \
  --mode vispec \
  --input-data /data/datasets/vispec_qwen2_5_vl/stage2_clean/data.jsonl \
  --media-dir /data/LLaVA-Pretrain --input-start 60000 \
  --num-prompts 64 --max-new-tokens 512 --fixed-output-length \
  --attn-implementation sdpa \
  --output training_logs/vispec_local_64x512.json
```

Without `--input-data`, the evaluator streams four representative ViSpec
benchmarks directly from Hugging Face: ScienceQA, MM-Vet, TextVQA, and COCO
Caption. Every sample generates exactly 512 tokens;
EOS does not terminate generation. Benchmark conversations contain only the
dataset-specific user message and image; no system prompt is injected. The
default is 100 prompts per benchmark.
For example, run the complete ViSpec suite with:

```bash
.venv/bin/python tools/transformers_vlm_spec_bench.py \
  --target /data/models/Qwen2.5-VL-7B-Instruct \
  --draft /data/models/ViSpec-Qwen2.5-VL-7B-Instruct-nemo \
  --mode vispec --num-prompts 100 --fixed-output-length \
  --baseline-results training_logs/baseline_representative_4x100x512.json \
  --attn-implementation sdpa \
  --output training_logs/vispec_representative_4x100x512.json
```

Use `--only scienceqa` (or another benchmark name) for a single-dataset run.
Use `--no-fixed-output-length` only for an intentional EOS-terminated diagnostic.
Use `--vispec-proposal-mode chain` for the no-tree ablation: the same ViSpec
draft still rolls out three recursive steps, but only its top-1 continuation is
retained at every depth.
Use `--benchmark-suite legacy` to run the original GQA, TextVQA, COCO Caption,
CharXiv Reasoning, and MMMU-Pro suite with the shared 256-token limit from
`examples/speculative/bench_sweep/vlm_spec_bench_datasets_legacy_256.yaml`.
The measured five-method comparison is recorded in
[`qwen2_5_vl_legacy5_4x256_results.md`](../bench_sweep/qwen2_5_vl_legacy5_4x256_results.md).
